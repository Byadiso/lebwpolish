# Account-linked progress — v4

## Behavior

| Learner | Saving behavior |
| --- | --- |
| Guest / signed out | Current browser and device only. Existing guest keys are preserved. |
| Signed in | Learning state is linked to the authenticated Firebase UID and loaded from the account on another device. |
| Account temporarily offline | Pending changes remain in an account-specific local cache where available. The interface does not claim they are saved to the account until the server confirms. |
| Different user signs in | A separate account cache and server record are used. Another user’s cached work is not displayed. |

The shared layer covers the journey, contextual vocabulary reviews, writing drafts, daily-goal and level preferences, B1 self-reflection, activity favourites, recent activity, saved reading state/cards, saved role-play favourites, saved Everyday Missions state, arcade fallback statistics, and guest-style lesson-completion records when signed in. Existing authenticated profile/lesson rewards continue to use their existing user-profile fields.

## Saving and conflicts

- Writes use Firestore transactions against `users/{uid}` and preserve unrelated profile fields.
- `learningData` maps application storage keys to serialized strings. `learningApplied` holds the latest 128 operation IDs to avoid replaying confirmed operations.
- Fast updates are coalesced and debounced for 300 ms; up to twenty queued operations can be committed in one transaction. Local cache updates are immediate.
- The queue survives a reload when browser storage is available. Retry sync or reconnect to retry failed writes.
- Journey mission IDs and activity days merge as sets, so completed missions from different devices are preserved without duplicate XP. Vocabulary reviews use the latest recorded review timestamp. Correct device clocks are assumed.
- Edits to different writing prompts are merged. Concurrent edits to the same prompt use server commit order; there is no collaborative text editor or draft version history.
- Other preferences and saved session positions use the latest committed value for that key.
- On first account load, the app waits for account data instead of uploading guest defaults. If account loading fails, it offers retry or sign-out to guest practice. A previously cached account can continue with an unsynced-status message.

## Earlier local progress

Earlier versions stored a journey in a shared guest browser key, even when a person happened to be signed in. That history cannot reliably be attributed to one person on a shared device. It is preserved, and Daily Journey offers **Import my guest journey** if there are guest mission completions missing from the signed-in account. Import only your own history. The guest copy is kept. Guest writing drafts and other guests’ activity are not imported automatically.

## Firebase setup

Keep the working Firebase configuration in `.env`. Existing Firestore access rules must allow an authenticated learner to read their own `users/{uid}` document and to write the `learningData` and `learningApplied` fields there. If a profile document is absent, the sync adapter creates a document containing those fields. Rules must permit that owned-document creation if your registration flow does not already create it.

No Firestore rules were deployed or replaced. Preserve your existing role/admin restrictions when adjusting rules. A denied read/write appears as an account-sync error with a retry action; it is not silently treated as a successful save.

## Verification

1. Run `npm test`, `npm run test:render`, and `npm run build`.
2. Signed out: complete a mission and confirm the guest/browser save message.
3. Sign in: confirm account data loads. Choose the guest-journey import if that history belongs to you.
4. Complete another mission and wait for **Progress saved to your account**.
5. In another browser/device, sign into the same account and check missions, review queue, preferences, and a writing draft.
6. Sign into a different account and confirm the first account’s work is absent.
7. Disconnect after a successful account load, make a change, and check the unsynced indicator. Reconnect or retry and verify confirmation before testing another device.
8. Check Firestore permission failures with your project’s own rules and verify they show an error rather than a false success.

Thirty-one regression tests, the production build, targeted new-code lint, and eighteen public-entry server-render checks pass. Account-sync unit tests use a simulated remote service. Live Firebase and browser interaction checks require the owner’s configuration and were not run here.

The Cloze game added in v5 uses the same account-aware store through a same-origin iframe bridge under `lebw.cloze.b1.v1`. Its standalone-file mode uses localStorage. It does not replace other modules’ saved data. Concurrent Cloze sessions use the latest committed game snapshot, so use one active device at a time for that game.

# LEBWPOLISH application review and implemented refresh

## Evaluation

The application has a strong collection of Polish activities and a recognisable visual identity. The main obstacles were discovery, disconnected progress, inconsistent interface icons, intimidating wording, and a few broken completion/reset paths. Several displayed achievements were examples rather than real learner activity.

The refresh creates a clearer route from curiosity to practice: choose a small mission, learn one pattern, try it with feedback, recall a phrase later, then use it in a conversation or a longer writing task. This is the design intent; engagement and learning gains have not been measured with users.

## Implemented changes

# One word closer — LEBWPOLISH B1 Cloze Lab

## Open the single-file game

Open `lebwpolish-cloze-b1.html` in a modern browser. HTML, CSS, vanilla JavaScript, sixty starter sentences, grammar hints, and SVG icons are all in this one file. No package installation, fonts, network assets, or external libraries are required. The font stack matches the app’s system-sans identity; red/slate colours and bold typography are retained.

Standalone progress is stored under its own localStorage key, `lebw.cloze.b1.v1`. Browsers handle local `file:` storage differently; if saving is unavailable, the footer warns you. Export a JSON backup before leaving. Device speech depends on installed browser/OS voices and may require the platform’s own connectivity.

## Open it inside the existing app

Use the complete v5 project, retain your existing `.env`, and run:

```bash
npm ci
npm run dev
```

Visit `/cloze` or find **One word closer** in Explore. The game remains a single independent HTML file, embedded by a small React wrapper. Guests use browser saving; signed-in learners use the account-aware saving layer from v4. The wrapper validates the message origin and iframe source and only accepts this game’s designated storage key. Firebase permissions/configuration from v4 are still required for account saves.

No earlier journey, reading, writing, profile, or vocabulary data is reset or replaced. Standalone-file browser storage and the hosted app’s browser storage are different origins; use a game backup to move between them.

## The learning loop

1. A session starts with due reviews, oldest first, followed by at most ten unseen sentences.
2. Fast Track orders new sentences by ascending `frequencyRank`. Turn it off to use library order. Starter ranks are illustrative priorities, not measured corpus frequencies; supplied corpus ranks are respected for imported entries.
3. Type the word and press Enter, or choose one of four distinct options. Capitalisation and extra surrounding spaces are ignored.
4. A diacritic-free equivalent is accepted as **almost**, while the correct spelling is shown. Other word endings are not treated as equivalent.
5. Feedback reveals the full sentence and its grammar hint. Press Enter on the feedback panel, click Next, or enable timed auto-next. Speech and other focused buttons retain their native keyboard actions.
6. Wrong answers return after up to three other queued cards. If no other cards remain, the retry is necessarily next after feedback. Finish for now is always available.

The model and scheduler are defined before the UI script, with a short explanation at the top of the code. Sentence data is in the embedded `starter-data` JSON block.

## Review schedule

| Accepted-answer mastery | Next review |
| --- | --- |
| 1 | 1 day |
| 2 | 2 days |
| 3 | 4 days |
| 4 | 8 days |
| 5 | 16 days |

Accepted includes correct and almost. Mastery is capped at five, and subsequent correct reviews at five remain sixteen days apart. Wrong answers reset to zero and stay due if the run is stopped. Future-due cards are not included in scored sessions.

Free play uses up to twenty introduced sentences, starting with lower mastery. It is unlimited and changes neither review dates nor XP/accuracy/streak statistics.

## Points and progress

- Exact typed answer: 20 XP.
- Typed answer missing Polish diacritics: 15 XP.
- Correct multiple choice: 10 XP.
- Wrong answer: 0 XP, with no subtraction.
- Re-submitting the same feedback cannot award duplicate points.
- Every 100 XP adds a level. These are game levels, not CEFR or exam scores.
- The progress screen shows mastered unique target forms (mastery five), accepted-answer accuracy, almost-answer counts, current streak, a rolling 28-day practice calendar, and mastery distribution.
- Any scored practice attempt counts as an active day; simply opening the game does not. A streak may continue from yesterday before you practise today.

## Add more sentences

Paste an array into Library:

```json
[
  {
    "id": "custom-001",
    "polish": "Czekam na twoją odpowiedź.",
    "english": "I am waiting for your answer.",
    "targetWord": "odpowiedź",
    "frequencyRank": 120,
    "grammarHint": "Accusative singular after czekać na.",
    "topic": "Daily life"
  }
]
```

The first five fields are required. Grammar hints and topics are optional; starter hints cover all sixty original sentences. For useful feedback on custom material, supply a grammarHint rather than relying on an automatically guessed rule.

The target must appear exactly once as a complete word, with the same spelling apart from capitalisation. Imports are validated before anything is changed. Identical existing IDs are skipped; conflicting IDs and duplicate imported IDs are rejected. Existing progress stays attached to its original sentence ID. HTML-like text is escaped when displayed. The library supports up to 10,000 entries, subject to browser storage limits.

Tatoeba-style data must be converted to the fields above; the app does not fetch Tatoeba. Verify licensing, attribution, translations, and frequency sources for any imported material. The starter set here is original content.

## Backups

Export a backup from Your progress. It includes the library, mastery, due dates, lifetime statistics, calendar, and settings. Choose a backup, review its summary, then explicitly restore it. Restoring replaces only this Cloze game’s data and starts without an unfinished quiz; other app progress is untouched. A regular reload can resume an in-progress saved run, including its existing feedback, without awarding the answer twice.

The integrated Cloze save is one account-backed game snapshot. Use one active device/session at a time; concurrent Cloze runs follow the shared store’s latest committed snapshot. Existing v4 journey merging is unchanged.

# LEBWPOLISH — learn by doing

Polish for real life, through short missions, sentence games, reading, speaking prompts, music, and writing. The original red/slate/white brand and existing module fonts are preserved.

## Start locally

Use Node.js 20.19+ or 22.12+.

```bash
npm ci
npm run dev
```

Open the exact local URL printed by Vite. Start with `/learn`, `/explore`, or `/B1-writing`.

The public practice tools work without Firebase configuration. To enable sign-in, saved account profiles, and community features, copy `.env.example` to `.env` and fill in your own Firebase project values. Keep an existing working `.env`; do not overwrite it with the empty example. Restart Vite after changing environment variables.

## Main learning flows

- **One word closer** (`/cloze`): a single-file B1 Cloze game with sixty original sentences, typing/four-choice modes, mastery-based reviews, streaks, XP, JSON imports, and backups. See `CLOZE-GUIDE.md`.
- **Daily Journey** (`/learn`): twelve A1–B1 missions, thirty-six short exercises, contextual phrases, optional hints, and everyday transfer prompts.
- **Memory Garden** (`/learn?tab=review`): recall before reveal, then schedule a phrase for review based on honest self-assessment.
- **B1 Compass** (`/learn?tab=b1`): five exam skill areas, a self-reflection checklist, and official practice links.
- **Explore** (`/explore`): searchable activity directory, skill filters, five-minute filter, favourites, recent activity, and a surprise activity.
- **Writing Studio** (`/B1-writing`): three original practice tasks, planning prompts, saved drafts, word counts, and self-review.
- Existing arcade, reading, listening, music, vocabulary, cases, conjugation, role-play, community writing, and administration routes remain available.

## Checks

```bash
npm test
npm run test:render
npm run build
```

`npm test` covers progress, scheduling, route integrity, and isolated resets. `test:render` checks initial server-rendered public screens and icon rendering; it does not simulate browser interactions. `npm run lint` also checks legacy modules, which still contain pre-existing lint findings. See `APP-REVIEW.md` for exact validation scope.

## Storage and audio

Guests keep their progress in the current browser on the current device. Signed-in learners save their journey, reviews, writing drafts, preferences, favourites, recent activity, and existing saved activity state to their Firebase account. Account-specific browser caches retain pending changes if sync fails; the UI reports whether a save is confirmed or still pending. Guest history is not attached to an account automatically. Daily Journey offers an explicit guest-journey import.

Cloud progress is stored in `users/{uid}.learningData`, with a bounded `learningApplied` list used to avoid replaying writes. Existing account profile fields are preserved. See `ACCOUNT-PROGRESS.md` for setup, migration, conflict handling, and verification. Audio examples use browser/device speech where implemented; Polish voice availability and quality vary.

## Exam preparation scope

The missions are a growing practice foundation, not a complete B1 course or an exam-readiness certification. Add authentic listening, full-length timed sample papers, and teacher feedback on writing and speaking. The adult exam information links to the official certyfikatpolski.pl resources.

## Interface icons

`src/components/AppIcon.jsx` provides local SVGs with a consistent stroke. Serializable `[icon:name]` tokens in content are presented through `IconText`. No icon font, icon CDN, or extra package is needed. User-authored content is not rewritten.

<script id="cloze-core">/* Scheduler: each session starts with due reviews, oldest first, then at most 10
   unseen sentences (Fast Track orders these by frequencyRank). A correct or
   diacritic-only “almost” answer raises mastery to 1–5 and schedules 1/2/4/8/16
   days ahead. A wrong answer resets mastery to 0, stays due, and re-enters after
   up to three other queued cards. Free play changes neither mastery nor XP.
   LEBWPOLISH uses its own storage key; existing app progress is never cleared. */
(() => {

  const DAY=86400000, KEY='lebw.cloze.b1.v1', DELAYS=[1,2,4,8,16];
